# 百度广告数据结构拉链表存储功能开发文档

## 1. 功能概述

本功能旨在将百度广告的数据结构以拉链表的形式存储快照，支持增量和全量更新，确保数据的历史追溯性和完整性。

### 1.1 核心需求
- 以拉链表形式存储百度广告数据结构快照
- 支持数据变化的增量存储
- 维护campaign、adgroup、keywords、creative四个核心实体
- autoExpansion作为特殊的keywords并入keywords表
- 建立完整的ORM模型关联关系

## 2. 数据模型设计

### 2.1 拉链表设计原则
- 使用`effective_date`和`expiry_date`字段标识数据有效期
- `expiry_date`为'9999-12-31'表示当前有效数据
- 数据变更时，更新旧记录的`expiry_date`，插入新记录

class CampaignSnapshot(BaseTableEnhanced):
    __tablename__ = "campaign_snapshot"
    
    # 主键
    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    
    # 业务主键
    campaign_id: Mapped[int] = mapped_column(BigInteger, nullable=False, comment="推广计划ID")
    user_name: Mapped[str] = mapped_column(VARCHAR(50), nullable=False, comment="账户名称")
    
    # 拉链表字段
    effective_date: Mapped[Date] = mapped_column(Date, nullable=False, comment="生效日期")
    expiry_date: Mapped[Date] = mapped_column(Date, nullable=False, default=date(9999, 12, 31), comment="失效日期")
    
    # 业务字段
    campaign_name: Mapped[str] = mapped_column(VARCHAR(200), comment="推广计划名称")
    status: Mapped[int] = mapped_column(Integer, comment="状态")
    budget: Mapped[float] = mapped_column(DECIMAL(15, 2), comment="预算")
    data_json: Mapped[dict] = mapped_column(JSON, comment="完整数据JSON")
    
    # 索引和约束
    __table_args__ = (
        UniqueConstraint("campaign_id", "user_name", "effective_date", name="uix_campaign_snapshot_key"),
        Index("idx_campaign_current", "campaign_id", "user_name", "expiry_date"),
        Index("idx_campaign_user_date", "user_name", "effective_date"),
        {"schema": "ads_structure"},
    )

## 3. 外键约束关系

### 3.1 层级关系
```
Campaign (推广计划)
    ├── AdGroup (推广单元)
    │   ├── Keyword (关键词)
    │   ├── AutoExpansion (自动拓词，存储在Keyword表中)
    │   └── Creative (创意)
```

### 3.2 外键约束设计

1. **AdGroup → Campaign**
   - 外键：`(campaign_id, user_name)`
   - 引用：`campaign_snapshot(campaign_id, user_name)`
   - 约束名：`fk_adgroup_campaign`

2. **Keyword → AdGroup**
   - 外键：`(adgroup_id, user_name)`
   - 引用：`adgroup_snapshot(adgroup_id, user_name)`
   - 约束名：`fk_keyword_adgroup`

3. **Keyword → Campaign**
   - 外键：`(campaign_id, user_name)`
   - 引用：`campaign_snapshot(campaign_id, user_name)`
   - 约束名：`fk_keyword_campaign`

4. **Creative → AdGroup**
   - 外键：`(adgroup_id, user_name)`
   - 引用：`adgroup_snapshot(adgroup_id, user_name)`
   - 约束名：`fk_creative_adgroup`

5. **Creative → Campaign**
   - 外键：`(campaign_id, user_name)`
   - 引用：`campaign_snapshot(campaign_id, user_name)`
   - 约束名：`fk_creative_campaign`

### 3.3 拉链表外键特殊处理

由于拉链表的特性，外键关系需要特殊处理：
- 外键约束只在数据库层面建立基本的引用完整性
- 应用层面通过SQLAlchemy relationship建立逻辑关系
- relationship中使用`primaryjoin`确保只关联当前有效数据（`expiry_date = '9999-12-31'`）

### 4.2 数据同步策略

1. **全量更新**
   - 将所有当前有效数据的`expiry_date`更新为当前日期
   - 插入新的完整数据集，`effective_date`为当前日期

2. **增量更新**
   - 比较新旧数据，识别变更记录
   - 对变更记录：更新旧记录`expiry_date`，插入新记录
   - 对删除记录：更新`expiry_date`为当前日期
   - 对新增记录：直接插入

### 4.3 查询功能

1. **当前结构查询**
   - 查询条件：`expiry_date = '9999-12-31'`

2. **历史结构查询**
   - 查询条件：`effective_date <= target_date AND expiry_date > target_date`
